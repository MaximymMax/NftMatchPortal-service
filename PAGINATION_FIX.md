# Исправления пагинации для недоступных страниц

## Проблема
- В базе данных (default endpoint) записаны только первые 3 страницы (150 элементов по 50 на страницу)
- API возвращает большее количество totalPages
- При попытке перейти на страницу >3 происходила ошибка и ломалась навигация
- Нужно было обеспечить возможность возврата на доступные страницы при ошибке

## Решение

### 1. Отображение всех страниц
В функции `renderDeals()`:
```javascript
// Показываем все страницы, которые возвращает API
totalPages = responseData.TotalPages || 1;
```

Теперь **ВСЕ страницы отображаются в пагинации**, независимо от того, доступны они в кеше или нет.

### 2. Автоматическое переключение на custom endpoint для страниц >3
В функции `fetchDeals()` добавлена логика:
```javascript
const isPageBeyondDefaults = queryToUse.page > 3;

if (isDefaultMode && isPageBeyondDefaults) {
    isDefaultMode = false; // для этого запроса используем custom endpoint
}
```

Когда пользователь пытается перейти на страницу >3 в default режиме, система **автоматически пытается загрузить данные через авторизованный custom endpoint**.

### 3. Обработка ошибок доступа
Если пользователь не авторизован (не в whitelist):
- ✅ Показывается модальное окно с информацией об ограничении доступа
- ✅ Текущие данные на странице **НЕ удаляются** - контент остается на месте
- ✅ Пользователь может закрыть модалку и продолжить работать с доступными страницами
- ✅ Номер страницы автоматически возвращается на предыдущую (доступную)

### 4. Умная навигация с откатом
В функциях `goToNextPage()` и `goToPreviousPage()`:
```javascript
async function goToNextPage() {
    if (isLoading) return;
    if (activeQuery.page < totalPages) {
        const previousPage = activeQuery.page;
        activeQuery.page++;
        const success = await fetchDeals();
        if (!success) {
            // Откат на предыдущую страницу при ошибке
            activeQuery.page = previousPage;
            updatePaginationControls();
        }
    }
}
```

## Поведение после изменений

### Сценарий 1: Неавторизованный пользователь (default режим)
1. **Видит все страницы** в индикаторе пагинации (например, "3 / 10")
2. Страницы 1-3: загружаются через **default endpoint** (быстро, из кеша)
3. Нажимает "next" на 3-й странице → попытка перейти на 4-ю:
   - Система пытается загрузить через **custom endpoint**
   - ❌ Ошибка 403/401 → показывается модалка "Donators Only"
   - ✅ Остается на странице 3, **контент не пропадает**
   - Может закрыть модалку и продолжить работу
4. Может свободно переключаться между страницами 1-3

### Сценарий 2: Авторизованный пользователь (в whitelist)
1. Видит все доступные страницы
2. Страницы 1-3: загружаются через **default endpoint** (быстро)
3. Страницы 4+: автоматически загружаются через **custom endpoint**
4. Может переходить на любую страницу без ограничений

### Сценарий 3: Изменение фильтров
Когда пользователь меняет фильтры (например, MinCoof < 80 или MaxMarkup > 30):
- Запрос автоматически идет через **custom endpoint** для всех страниц
- Если нет доступа → модалка при первом же запросе
- Может вернуться к дефолтным фильтрам и продолжить работу

## Ключевые преимущества

✅ **Прозрачность**: пользователь видит все доступные страницы  
✅ **Плавный UX**: контент никогда не пропадает  
✅ **Умная загрузка**: страницы 1-3 быстро из кеша, 4+ через API  
✅ **Безопасность**: при ошибке автоматический откат без потери данных  
✅ **Информативность**: понятная модалка объясняет ограничение  

## Исправленные файлы
- `script.js` - основная логика приложения
  - `fetchDeals()` - автоматическое переключение endpoint
  - `renderDeals()` - отображение всех страниц
  - `goToNextPage()` / `goToPreviousPage()` - откат при ошибках
